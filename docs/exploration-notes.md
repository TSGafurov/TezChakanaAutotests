# Chakana Express (uz.agrobank.chakanaexpress) — exploration notes & test plan

Собрано в ходе живого исследования приложения на эмуляторе (adb/Appium) 2026-08-22.
Дополняет `src/test/java/com/tezchakana/tests/CheckoutFlowTest.java` и `BaseTest.java`.

## Контекст тестового окружения

- Приложение — Flutter-based, accessibility-дерево скудное: элементы часто смерджены в один
  content-desc-узел на весь экран, resource-id почти нет. Основной паттерн: реальная зона тапа
  кнопки внизу экрана (y≈2184 из 2400), а не там, где кнопка визуально нарисована — см. `BOTTOM_CTA_X/Y`
  в `CheckoutFlowTest`. Встречается минимум на 5+ экранах (мини-корзина, логин, OTP, чекаут,
  оформление заказа) — кандидат на общий хелпер вместо копирования координат.
- `uiautomator dump` часто отдаёт `ERROR: could not get idle state` на анимированных экранах —
  надёжнее ориентироваться на скриншоты + явные wait, а не только на дерево доступности.
- Тестовый номер телефона (`909023162`, зашит в `CheckoutFlowTest`) — это **реальный личный аккаунт**
  владельца проекта, не изолированный QA-аккаунт. На нём реальные заказы, адреса, сохранённые карты.
  Оформление заказа списывает реальные деньги (возвратно). Перед автоматизацией полного чекаута —
  see "Known issues" ниже.
- Диалог "Allow notifications?" появляется заново при **каждом** перезапуске приложения, даже с
  сохранённой сессией логина, т.к. `BaseTest` использует `setAutoGrantPermissions(false)`.

## Known issues / flaky points

1. **Оплата падает с ошибкой бэкенда**: кнопка "Buyurtma qilish" (оформить заказ) стабильно
   завершалась ошибкой `dio_error: connection_error` (3/3 попытки в одной сессии). Интернет хоста
   и остальные вызовы на том же экране работали нормально — похоже на проблему бэкенда/окружения,
   а не тестового кода. Побочных эффектов не было (дублей заказа не создавалось, корзина не терялась).
2. **"Mening kartalarim" (мои карты) не грузится**: `Xatolik ro'y berdi` без кнопки retry,
   воспроизведено в 2 из 2 сессий подряд — похоже на устойчивую, не разовую проблему.
3. **Возможный баг фильтрации категорий**: чипы Bazar/Gullar/Kafe/Qandolat на Home визуально
   переключаются, но список "Yaqin atrofdagi do'konlar" не меняется — под Kafe/Gullar показывались
   те же магазины, что и под "Hammasi". Требует перепроверки на стабильном бэкенде.
4. Список магазинов "Yaqin atrofdagi do'konlar" и открытие карточки магазина также несколько раз
   падали с `Xatolik ro'y berdi` во второй сессии разведки — вместе с (1) и (2) похоже на
   временную деградацию бэкенда в моменте исследования, стоит перепроверить отдельно.
5. **"Xabarnomalar" (уведомления) не пустой экран**, а долго грузится (~8-10 сек) — при коротком
   таймауте тест ошибочно решит, что список пуст.
6. **Тап по прокрученной плитке категории магазина нестабилен** (воспроизведено 2026-08-25,
   5/5 попыток на плитке "Suv" в категориях "Eco Bazar"): `scroll_to_element` до плитки "Suv"
   (3 свайпа вниз) рапортует успех, но последующий тап по ней — через найденный элемент, через
   координаты его центра, с задержками 1–3 сек после скролла — либо откатывает экран назад на
   Home, либо не срабатывает вовсе. Один раз между двумя проверками `bounds` той же плитки
   зафиксирован сдвиг ~200px без дополнительного скролла — список, похоже, продолжает "доезжать"
   после того как `scroll_to_element` уже посчитал прокрутку завершённой. Тап по категории в
   самом верху списка (без скролла, например "Uy uchun bozorlik") при этом отрабатывает
   стабильно — проблема специфична для прокрученных плиток, а не для тапа по категориям вообще.
   **Важно**: `CheckoutFlowTest.completeCheckoutWithCashOnDelivery` скроллит к той же плитке
   "Suv" тем же способом (`StoreScreen.scrollToCategory`) — этот тест может сейчас флакать по
   той же причине. Существующий тест не менялся, чтобы не полагаться на непроверенный фикс;
   если он начнёт падать на `scrollToCategory("Suv")`, это, вероятно, та же проблема, а не
   баг локатора. См. [[project-scroll-tap-flakiness]] в памяти.
7. **Добавление товара в корзину не всегда закрепляется бэкендом**: тап "+" на карточке товара
   иногда даёт лишь оптимистичное обновление UI (счётчик на карточке становится "1"), которое
   через 1–2 сек откатывается обратно к "0" без ошибки на экране — на повторной попытке то же
   действие закрепляется нормально. Похоже на тот же тип нестабильности бэкенда, что и в (1)/(4),
   но затрагивает не только оформление заказа, а базовое добавление в корзину. Тестам, зависящим
   от результата добавления в корзину, стоит перепроверять состояние (или ретраить) вместо
   однократного тапа с последующим немедленным ассертом.
8. **Диалог подтверждения адреса на старте — не только на первом запуске**: карта
   флоу ниже и ONB-01 описывают его как часть флоу именно первого запуска ("Первый
   запуск на чистых данных → геолокация → подтверждение адреса"). Проверено 2026-08-25:
   диалог "Shu manzilga buyurtma berilsinmi?" воспроизводится при **каждом полном
   перезапуске процесса** приложения (`terminate` + `activate`), не только на чистых
   данных — `NoReset(true)` это не убирает, автоматизировать можно без `pm clear`. Для
   диалога разрешения на уведомления ("Allow notifications?", строка выше) верно
   обратное: однажды выданное разрешение (`adb shell dumpsys package ...
   POST_NOTIFICATIONS: granted=true`) больше не запрашивается повторно на рестартах —
   обычное поведение Android для уже выданного разрешения, а не баг приложения. Раньше
   казалось, что оба диалога одинаково переживают рестарт - на практике это верно
   только для адреса, не для уведомлений (как только разрешение реально выдано).
9. **Тесты флакают пачками при большом количестве подряд идущих Appium-сессий, а не
   поодиночке**: 10 `@Test` в одном классе (`HomeAndCatalogTest`), каждый в своей
   Appium-сессии (`BaseTest` создаёт новую на каждый `@Test`), стабильно давали 7/10
   падений с `TimeoutException` на `waitFor(Bazar/Hammasi/...)` при прогоне подряд
   (~100-140 сек суммарно, воспроизведено дважды подряд с идентичным набором
   упавших/прошедших тестов). При этом: (а) те же самые тесты по одному или маленькими
   группами (2-3) проходят чисто каждый раз; (б) устройство/приложение в момент проверки
   между прогонами были живы и на Home без проблем; (в) тест с `terminateApp`/`activateApp`
   (полный рестарт процесса) в середине прогона коррелирует с тем, что следующий за ним
   тест проходит, как будто временно "чинит" деградацию. Похоже на деградацию
   производительности эмулятора/UiAutomator2-инструментации от быстрой последовательной
   пересоздачи сессий, а не на баг локаторов/кода — не путать с багом конкретного теста,
   если он падает только в составе большого прогона, но проходит в изоляции. Актуально
   для планирования CI: батчи тестов в один прогон стоит держать небольшими, или
   закладывать ретраи на уровне рантайма/CI, а не только на уровне отдельных локаторов.

## Карта экранов и флоу

```
Home (Bosh sahifa)
 ├─ Header: адрес ▾, избранное (сердце, верх справа)
 ├─ Категории-чипы: Hammasi | Bazar | Gullar | Kafe | Qandolat  (визуально фильтруют, реально — нет, см. issue 3)
 ├─ Промо-баннер (свайп)
 ├─ Список "Yaqin atrofdagi do'konlar": Eco Bazar, Suvenir.uz, Lazzat Norin, ... (подгружается при скролле;
 │   зависит от адреса доставки — Avigo/Everest не показывались для адреса в Наманганской обл.)
 ├─ Нижняя навигация: Home | Savat | Profile
 └─ Запуск → геолокация (сист.) → "Shu manzilga buyurtma berilsinmi?" [Ha, men shu yerdaman | Manzilni o'zgartirish]
    + диалог "Allow notifications?" на каждом запуске

Store screen (Eco Bazar, Suvenir.uz, ...)
 ├─ Header: назад, лого/название, поиск (иконка не локализована в разведке — доразведать)
 ├─ Категории (напр. "Suv") → сетка товаров
 ├─ Карточка товара → тап "+" (только координаты, локатора нет)
 └─ Плашка корзины ("N mahsulot") → мини-корзина

Мини-корзина ("Savat", bottom sheet)
 ├─ Магазин, товар(ы), "Tozalash" (очистить), +/- количество
 ├─ Блок рекомендаций "Hech narsani unutmadingizmi?"
 └─ "Savat\nTo'lovga o'tish" → чекаут (для гостя — сперва логин)

Login flow (гость)
 Kirish (шторка, non-clickable node, coord-tap) → номер телефона → "Davom etish"
   → OTP (6 ячеек, resend cooldown 30с) → Tasdiqlash

Checkout ("Xarid qilish") — авторизованный идёт сюда сразу из мини-корзины
 ├─ Yetkazib berish tafsilotlari: способ доставки, ETA ("Yaqin 2 soat"), получатель (имя+телефон),
 │   "Kuryerga izoh qoldirish"
 ├─ To'lov usuli → шторка: "Naqd pul" | "Karta orqali" (радио + Tasdiqlash)
 ├─ Promokod (не исследовано)
 ├─ Итоговая сумма
 └─ Нижняя CTA: неактивна пока не выбран способ оплаты → "Buyurtma qilish" (активна)
      → см. Known issue 1 (падает с dio_error)
      → error-state: полноэкранный "Xato" / "Bosh sahifa" / "Qayta urinib ko'ring"

Profile
 Гость: заглушка аватара, "Kirish", Sevimlilar | Yordam | Sozlamalar
 Авторизован: аватар, имя, карточка последнего заказа (координаты строк ниже СМЕЩАЮТСЯ в
   зависимости от наличия этой карточки — всегда свежий скриншот перед тапом), затем:
   Mening tafsilotlarim | Manzillar | Mening kartalarim | Xabarnomalar | Sozlamalar | Hisobdan chiqish
 ├─ Sevimlilar → shimmer (~4-5с) → список/пусто
 ├─ Yordam → открывает ВНЕШНИЙ Chrome, не веб-вью в приложении
 ├─ Manzillar → список сохранённых адресов + "Manzil qo'shish"
 ├─ Mening tafsilotlarim → Ism, Telefon (read-only), E-mail, "Instagram/Telegram qo'shish",
 │   "Saqlash" (неактивна без изменений), внизу — "Hisobni o'chirish" (удалить аккаунт)
 ├─ Mening kartalarim → см. Known issue 2
 ├─ Xabarnomalar → см. Known issue 5
 ├─ Sozlamalar → Til (O'zbekcha/Ўзбекча/Русский), тумблер уведомлений (сейчас OFF),
 │   Ko'p beriladigan savollar (FAQ), Ilova maxfiylik siyosati, версия (V 1.1.8 (2043))
 └─ Hisobdan chiqish → диалог подтверждения ("Haqiqatan ham...?" / Bekor qilish / confirm)

Buyurtmalar (заказы)
 ├─ Faol/история, статус-степпер (4 стадии)
 └─ Деталь заказа → красная иконка отмены → диалог "Buyurtmani bekor qilish"
      (+ необязательное поле причины) → "Yo'q" | "Buyurtmani bekor qilish"
```

## Не исследовано

Поиск (иконка не найдена на Home), содержимое категорий Gullar/Kafe/Qandolat, магазины
Avigo/Everest oshxonasi, оплата картой (Karta orqali), промокод, добавление адреса/карты,
удаление аккаунта, реальная отмена заказа, реальное завершение оформления заказа (блокировано
Known issue 1).
